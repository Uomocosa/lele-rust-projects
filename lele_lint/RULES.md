# lele_lint rules

Generated by `lele_lint --rules-md`; do not edit by hand. Regenerate with
`LELE_BLESS=1 cargo nextest run --test rules_md` (the test fails while this file is stale).

Every rule is always on and always an error. `lele_lint --explain <CODE>` prints one rule.

Each example is a whole crate. Files not shown get these defaults: an empty `src/lib.rs`,
and a `Cargo.toml`, `clippy.toml` and `lele.toml` that already satisfy E021 and E022.
Every **Bad** example reports its rule's code (it may report others too);
every **Good** example reports nothing at all.

## Layout: files and folders

- [E001 `atomic_file`](#e001-atomic_file): One public item per file, and the file is named after it (`greet.rs` holds `pub fn greet`).
- [E002 `snake_case_files`](#e002-snake_case_files): File and folder names are snake_case.
- [E015 `helper_count`](#e015-helper_count): A file has one public function; at most 2 private helpers unless each is marked `// needed helper: <why>`.
- [E017 `method_file_co_location`](#e017-method_file_co_location): A `<type>_<method>.rs` file must sit in the same folder as `<type>.rs`.
- [E019 `mod_rs_purity`](#e019-mod_rs_purity): `mod.rs` holds only `mod`/`pub mod` declarations and `pub use` re-exports.
- [E026 `constants_placement`](#e026-constants_placement): A constant lives in the nearest `constants.rs` (or `__basic__/constants.rs`) shared by all its users.
- [E029 `container_placement`](#e029-container_placement): Behavior-free types (plain structs, enums, newtypes, aliases, ECS markers) go in the domain's `__basic__/<role>.rs`.

### E001 `atomic_file`

One public item per file, and the file is named after it (`greet.rs` holds `pub fn greet`).

**Why:** A file name tells you exactly what is inside; finding code means finding a file, and every unit gets its own test.

**Bad** (reports E001):

`src/lib.rs`

```rust
mod greeting;
pub use greeting::{farewell, greet};
```

`src/greeting.rs`

```rust
pub fn greet(name: &str) -> String {
    format!("Hello, {name}!")
}

pub fn farewell(name: &str) -> String {
    format!("Bye, {name}!")
}
```

**Good:**

`src/lib.rs`

```rust
mod farewell;
mod greet;
pub use farewell::farewell;
pub use greet::greet;
```

`src/greet.rs`

```rust
pub fn greet(name: &str) -> String {
    format!("Hello, {name}!")
}

#[cfg(test)]
mod tests {
    use super::greet;

    #[test]
    fn test_usage() {
        assert_eq!(greet("Ada"), "Hello, Ada!");
    }
}
```

`src/farewell.rs`

```rust
pub fn farewell(name: &str) -> String {
    format!("Bye, {name}!")
}

#[cfg(test)]
mod tests {
    use super::farewell;

    #[test]
    fn test_usage() {
        assert_eq!(farewell("Ada"), "Bye, Ada!");
    }
}
```

### E002 `snake_case_files`

File and folder names are snake_case.

**Why:** Module names are derived from file names; one casing keeps paths predictable.

**Bad** (reports E002):

`src/lib.rs`

```rust
#[path = "Greet.rs"]
mod greet;
pub use greet::greet;
```

`src/Greet.rs`

```rust
pub fn greet(name: &str) -> String {
    format!("Hello, {name}!")
}

#[cfg(test)]
mod tests {
    use super::greet;

    #[test]
    fn test_usage() {
        assert_eq!(greet("Ada"), "Hello, Ada!");
    }
}
```

**Good:**

`src/lib.rs`

```rust
mod greet;
pub use greet::greet;
```

`src/greet.rs`

```rust
pub fn greet(name: &str) -> String {
    format!("Hello, {name}!")
}

#[cfg(test)]
mod tests {
    use super::greet;

    #[test]
    fn test_usage() {
        assert_eq!(greet("Ada"), "Hello, Ada!");
    }
}
```

### E015 `helper_count`

A file has one public function; at most 2 private helpers unless each is marked `// needed helper: <why>`.

**Why:** Helpers pile up silently; the marker forces a reason for every extra function, and unexplained ones get their own file.

**Bad** (reports E015):

`src/lib.rs`

```rust
mod score;
pub use score::score;
```

`src/score.rs`

```rust
pub fn score(hits: u32, misses: u32) -> u32 {
    bonus(hits).saturating_add(base(hits)).saturating_sub(penalty(misses))
}

fn base(hits: u32) -> u32 {
    hits.saturating_mul(10)
}

fn bonus(hits: u32) -> u32 {
    if hits > 10 { 50 } else { 0 }
}

fn penalty(misses: u32) -> u32 {
    misses.saturating_mul(5)
}

#[cfg(test)]
mod tests {
    use super::score;

    #[test]
    fn test_usage() {
        assert_eq!(score(1, 0), 10);
    }
}
```

**Good:**

`src/lib.rs`

```rust
mod score;
pub use score::score;
```

`src/score.rs`

```rust
pub fn score(hits: u32, misses: u32) -> u32 {
    bonus(hits).saturating_add(base(hits)).saturating_sub(penalty(misses))
}

// needed helper: points per hit
fn base(hits: u32) -> u32 {
    hits.saturating_mul(10)
}

// needed helper: streak bonus above 10 hits
fn bonus(hits: u32) -> u32 {
    if hits > 10 { 50 } else { 0 }
}

// needed helper: points lost per miss
fn penalty(misses: u32) -> u32 {
    misses.saturating_mul(5)
}

#[cfg(test)]
mod tests {
    use super::score;

    #[test]
    fn test_usage() {
        assert_eq!(score(1, 0), 10);
    }
}
```

### E017 `method_file_co_location`

A `<type>_<method>.rs` file must sit in the same folder as `<type>.rs`.

**Why:** A method file that drifts away from its type is impossible to find from the type.

**Bad** (reports E017):

`src/lib.rs`

```rust
pub mod game;
pub mod player;
```

`src/player/mod.rs`

```rust
mod player;

pub use player::Player;
```

`src/player/player.rs`

```rust
pub struct Player {
    pub name: String,
    pub health: u32,
}

impl Default for Player {
    fn default() -> Self {
        Self {
            name: String::new(),
            health: 100,
        }
    }
}
```

`src/game/mod.rs`

```rust
mod player_rename;

pub use player_rename::rename;
```

`src/game/player_rename.rs`

```rust
use crate::player;

pub fn rename(player: &mut player::Player, name: String) {
    player.name = name;
}
```

**Good:**

`src/lib.rs`

```rust
pub mod player;

#[path = "../methods/mod.rs"]
pub mod methods;
```

`src/player/mod.rs`

```rust
mod player;

pub use player::Player;
```

`src/player/player.rs`

```rust
use atomic_delegate_macros::atomic_delegates;

pub struct Player {
    pub name: String,
    pub health: u32,
}

impl Default for Player {
    fn default() -> Self {
        Self {
            name: String::new(),
            health: 100,
        }
    }
}

#[atomic_delegates]
impl Player {
    pub fn heal(&mut self, amount: u32) {}
}

#[cfg(test)]
mod tests {
    use crate::player;

    #[test]
    fn test_usage() {
        let mut player = player::Player::default();
        player.heal(5);
        assert_eq!(player.health, 100);
    }
}
```

`methods/mod.rs`

```rust
pub mod player;
```

`methods/player/mod.rs`

```rust
mod heal;
pub use heal::heal;
```

`methods/player/heal.rs`

```rust
use crate::player;

pub fn heal(player: &mut player::Player, amount: u32) {
    let healed = player.health.saturating_add(amount);
    player.health = healed.min(100);
}

#[cfg(test)]
mod tests {
    use super::heal;
    use crate::player::Player;

    #[test]
    fn test_usage() {
        let mut player = Player {
            name: String::new(),
            health: 10,
        };
        heal(&mut player, 5);
        assert_eq!(player.health, 15);
    }
}
```

### E019 `mod_rs_purity`

`mod.rs` holds only `mod`/`pub mod` declarations and `pub use` re-exports.

**Why:** `mod.rs` is the folder's table of contents; logic hidden there is logic nobody looks for.

**Bad** (reports E019):

`src/lib.rs`

```rust
pub mod greeting;
```

`src/greeting/mod.rs`

```rust
pub fn greet(name: &str) -> String {
    format!("Hello, {name}!")
}
```

**Good:**

`src/lib.rs`

```rust
pub mod greeting;
```

`src/greeting/mod.rs`

```rust
mod greet;

pub use greet::greet;
```

`src/greeting/greet.rs`

```rust
pub fn greet(name: &str) -> String {
    format!("Hello, {name}!")
}

#[cfg(test)]
mod tests {
    use super::greet;

    #[test]
    fn test_usage() {
        assert_eq!(greet("Ada"), "Hello, Ada!");
    }
}
```

### E026 `constants_placement`

A constant lives in the nearest `constants.rs` (or `__basic__/constants.rs`) shared by all its users.

**Why:** Constants placed too high leak across domains; placed too low they get duplicated.

**Bad** (reports E026):

`src/lib.rs`

```rust
pub mod constants;
pub mod player;
```

`src/constants.rs`

```rust
pub const MAX_HEALTH: u32 = 100;
```

`src/player/mod.rs`

```rust
mod clamp_health;

pub use clamp_health::clamp_health;
```

`src/player/clamp_health.rs`

```rust
use crate::constants;

pub fn clamp_health(health: u32) -> u32 {
    health.min(constants::MAX_HEALTH)
}

#[cfg(test)]
mod tests {
    use super::clamp_health;

    #[test]
    fn test_usage() {
        assert_eq!(clamp_health(150), 100);
    }
}
```

**Good:**

`src/lib.rs`

```rust
pub mod player;
```

`src/player/mod.rs`

```rust
mod clamp_health;
#[path = "__basic__/mod.rs"]
pub mod basic;

pub use basic::constants::MAX_HEALTH;
pub use clamp_health::clamp_health;
```

`src/player/__basic__/mod.rs`

```rust
pub mod constants;
```

`src/player/__basic__/constants.rs`

```rust
pub const MAX_HEALTH: u32 = 100;
```

`src/player/clamp_health.rs`

```rust
use crate::player;

pub fn clamp_health(health: u32) -> u32 {
    health.min(player::MAX_HEALTH)
}

#[cfg(test)]
mod tests {
    use super::clamp_health;

    #[test]
    fn test_usage() {
        assert_eq!(clamp_health(150), 100);
    }
}
```

### E029 `container_placement`

Behavior-free types (plain structs, enums, newtypes, aliases, ECS markers) go in the domain's `__basic__/<role>.rs`.

**Why:** Small data types don't need a file and a test each; grouping them keeps atomic files for code that does something.

**Bad** (reports E029):

`src/lib.rs`

```rust
pub mod stock;
```

`src/stock/mod.rs`

```rust
mod item;

pub use item::Item;
```

`src/stock/item.rs`

```rust
pub struct Item {
    pub name: String,
    pub price: u32,
}
```

**Good:**

`src/lib.rs`

```rust
pub mod stock;
```

`src/stock/mod.rs`

```rust
#[path = "__basic__/mod.rs"]
pub mod basic;

pub use basic::structs::Item;
```

`src/stock/__basic__/mod.rs`

```rust
pub mod structs;
```

`src/stock/__basic__/structs.rs`

```rust
pub struct Item {
    pub name: String,
    pub price: u32,
}
```

## Delegates: methods and `methods/`

- [E003 `method_visibility`](#e003-method_visibility): A method file is a private module: declared with `mod`, never `pub mod` or `pub use`.
- [E012 `atomic_delegates`](#e012-atomic_delegates): Hand-written methods have at most 3 statements, and an impl block with one-line methods carries `#[rustfmt::skip]`.
- [E013 `constructor_no_skip`](#e013-constructor_no_skip): `impl Default` and real constructors are never `#[rustfmt::skip]`.
- [E030 `methods_layout`](#e030-methods_layout): Every `#[atomic_delegates]` shell has a body at `methods/<type>/<method>.rs` with `pub fn <method>`, 2+ statements and its own `test_usage`.
- [E032 `delegate_macro`](#e032-delegate_macro): Method shells (empty bodies) are declared in one `#[atomic_delegates]` impl block per type; `new` is never delegated.

### E003 `method_visibility`

A method file is a private module: declared with `mod`, never `pub mod` or `pub use`.

**Why:** Method bodies are reached only through the type's methods, so callers can't depend on the file layout.

**Bad** (reports E003):

`src/lib.rs`

```rust
pub mod player;
```

`src/player/mod.rs`

```rust

pub mod player_rename;

pub use player::Player;
```

`src/player/player.rs`

```rust

    pub health: u32,
}

    fn default() -> Self {
        Self {
            name: String::new(),
            health: 100,
        }
    }
}
```

`src/player/player_rename.rs`

```rust
use crate::player;

pub fn rename(player: &mut player::Player, name: String) {
    player.name = name;
}
```

**Good:**

`src/lib.rs`

```rust
pub mod player;

#[path = "../methods/mod.rs"]
pub mod methods;
```

`src/player/mod.rs`

```rust

```

`src/player/player.rs`

### E012 `atomic_delegates`

Hand-written methods have at most 3 statements, and an impl block with one-line methods carries `#[rustfmt::skip]`.

**Why:** Longer methods belong in `methods/<type>/<method>.rs`; short ones stay readable as one line each.

**Bad** (reports E012):

`src/lib.rs`

```rust
pub mod player;
```

`src/player/mod.rs`

```rust
mod player;

pub use player::Player;
```

`src/player/player.rs`

```rust
pub struct Player {
    pub name: String,
    pub health: u32,
}

impl Default for Player {
    fn default() -> Self {
        Self {
            name: String::new(),
            health: 100,
        }
    }
}

impl Player {
    pub fn is_alive(&self) -> bool {
        self.health > 0
    }
}
```

**Good:**

`src/lib.rs`

```rust
pub mod player;
```

`src/player/mod.rs`

```rust
mod player;

pub use player::Player;
```

`src/player/player.rs`

```rust

    pub name: String,
    pub health: u32,
}

    fn default() -> Self {
        Self {
            name: String::new(),
            health: 100,
        }
    }
}

}

#[cfg(test)]

    use crate::player;

    #[test]
    fn test_usage() {
        assert!(player::Player::default().is_alive());
    }
}
```

### E021 `clippy_config_cargo`

`Cargo.toml` has `[lints.clippy]` with `pedantic`/`nursery` denied at priority -1 and the 13 required deny lints (or inherits them from the workspace).

**Why:** Every crate gets the same strict baseline, so no crate silently allows unwraps, panics or lossy casts.

**Bad** (reports E021):

`Cargo.toml`

```toml
[package]
name = "example"
version = "0.1.0"
edition = "2021"
```

**Good:**

`Cargo.toml`

```toml
[package]
name = "example"
version = "0.1.0"
edition = "2021"

[lints.clippy]
pedantic = { level = "deny", priority = -1 }
nursery = { level = "deny", priority = -1 }
unwrap_used = "deny"
expect_used = "deny"
indexing_slicing = "deny"
arithmetic_side_effects = "deny"
unreachable = "deny"
unimplemented = "deny"
unchecked_time_subtraction = "deny"
todo = "deny"
string_slice = "deny"
panic_in_result_fn = "deny"
panic = "deny"
exit = "deny"
as_conversions = "deny"
```

### E022 `clippy_config_clippy`

`clippy.toml` sets `allow-unwrap-in-tests`, `allow-expect-in-tests`, `allow-panic-in-tests` and `allow-indexing-slicing-in-tests` to `true`.

**Why:** Tests may unwrap and index freely; production code may not.

**Bad** (reports E022):

`clippy.toml`

```toml
allow-unwrap-in-tests = true
```

**Good:**

`clippy.toml`

```toml
allow-unwrap-in-tests = true
allow-expect-in-tests = true
allow-panic-in-tests = true
allow-indexing-slicing-in-tests = true
```
